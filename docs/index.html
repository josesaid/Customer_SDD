Spec-Driven Development · Spring Boot

Customer_SDD

A customer CRUD REST API where every operation is written first in a spec, covered by tests that carry the spec ID, and only then implemented.

View source on GitHub Read the spec All projects

Stack

  • Java 21
  • Spring Boot 3.5.4
  • Spring Data JPA
  • Bean Validation
  • H2 in-memory
  • RFC 7807 ProblemDetail
  • JUnit 5 + MockMvc
  • Maven

How SDD works here

01 · SPEC

Write the spec

docs/specs/customer.md defines the entity, operations CUST-01 to CUST-05, status codes and error format.

02 · TEST

Trace it in tests

Each test names its operation ID in @DisplayName. 14 tests cover every rule.

03 · CODE

Implement

Controller, service and repository change until mvn test passes.

Endpoints

IDMethodPathResult
CUST-01POST/api/customers201 + Location · 400 · 409 duplicate email
CUST-02GET/api/customers/{id}200 (also inactive) · 404
CUST-03GET/api/customers?active=200, sorted by last name
CUST-04PUT/api/customers/{id}200 · 400 · 404 · 409
CUST-05DELETE/api/customers/{id}204 logical, idempotent · 404

Design notes

  • Emails are trimmed, stored in lowercase and must be unique.
  • Delete is logical: it sets active = false and keeps the record.
  • All errors are RFC 7807 ProblemDetail; validation errors include a per-field errors map.
  • Layers: CustomerController → CustomerService → CustomerRepository → H2.

Run it

mvn test               # spec tests
mvn spring-boot:run    # http://localhost:8080

curl -i -X POST localhost:8080/api/customers \
  -H 'Content-Type: application/json' \
  -d '{"firstName":"Ana","lastName":"Lopez","email":"ana@example.com"}'
